## Native evidence classification

- **E — existing exposed contract:** inspected client and bridge path exists. This is source evidence, not a fresh acceptance pass.
- **P — partial exposure:** related data/operation exists, but the entire pattern is not backed by a verified contract.
- **B — bridge extension candidate:** structured UI is ready; exact supported native payload needs discovery and a bounded typed adapter before activation.
- **N — no verified operational contract:** prepare all UI/states; no live action until explicit native semantics and isolated tests establish support. This does not claim the feature is absent from all upstream Hermes versions.
- **L — local presentation:** no native feature required; still cannot trigger hidden model calls.

Capability state and UI readiness are separate columns. Every AI row must reach **component + typed states + synthetic specimens + behavioral/visual checks ready** during U2, regardless of native classification. Specimens never enable a native action. Live unavailable operations are omitted unless an explanatory read-only state is relevant to the current user task.

## Coverage completion rules

For each catalog entry record component/alias, state cases, native evidence class, installed callers (or reserve), test/capture paths and last verified revision. Existing tests are starting points, not proof of unexercised behavior. The implementation must add focused tests for uncovered states revealed by U0; no requirement for meaningless tests of markup implementation details.

No optional native feature may activate until D3–D5's relevant evidence passes. No screen migration is complete while a competing old implementation or global CSS path still owns the same behavior. No system-completeness claim is valid with an unprepared AI pattern, even when its native capability is unavailable.
