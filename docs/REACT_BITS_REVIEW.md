# React Bits assessment for Pebble Crew

Recommendation: use React Bits as a reference for a few small interactions. Do not install its registry into Pebble Crew or replace the existing chat, panel, select, or avatar systems. The best opportunities are tooltip timing, the transition from live activity to a settled conversation, and a small send/stop glyph transition. No whole component earns an unconditional adoption recommendation.

This is source inspection, not a performance benchmark or a claim that the installed app has a demonstrated visual defect. No product code, dependencies, services, models, or owner data were changed. The only authored artifact is this report. The parent review visually inspected the official Thought Line working/settled preview and Prompt Bar multiline/attachment-menu preview in Chrome. Those observations are not a performance measurement. Throughput checkpoint: n/a, read-only investigation.

## Evidence and existing foundation

Inspected current public documentation and TypeScript/CSS implementation at React Bits revision **310fc737fadcaa149a4e06fb088fc95332dc8bfb**, using its registry JSON to verify dependencies. Local checkout is `/Users/assistant/Projects/Hermes-Bot-Mode-App`, HEAD `a0e364b39054164098097e2b8a46b21098688701`. Existing uncommitted `ui/layout.css` and `test/mobile/bubbles.spec.ts` were not changed. Working-tree CSS, rather than HEAD alone, informed this review.

Pebble already has:

- `ui/foundation.css`: neutral dark palette, 120/160/240ms motion tokens, native system typography, coarse-pointer 16px form text, and a CSS reduced-motion override.
- `ui/layout.css:457`: a reserved 28px activity lane, an actual CSS shimmer, and a specific static reduced-motion presentation. `chat/activity.ts` maps real tool names to short labels such as “Reading files.”
- `chat/Transcript.tsx`: native `<details>` activity groups, stable receipt keys, one entrance per genuinely new row, and reduced-motion-aware message entry. `chat/viewport-motion.ts` gives `TranscriptFollow` sole responsibility for animated following.
- `ui/DetailsDock.tsx`: one MotionValue drives the main boundary and fixed-width adjacent panel, using 240ms motion or zero duration for reduced motion. `chat/Drawer.tsx` retains Radix dialogs/sheets, focus restoration, unsaved-edit guards, and overlay history. This already implements the physical continuity we want.
- `App.tsx:1895`: controlled per-conversation drafts, actual attachment capabilities and upload readiness, IME-aware Enter handling, cancellation and stopping states. The composer is not just a decorative textarea.
- `ui/pebble-profile-fields.tsx`: shared identity/avatar fields, separate role details, and a Radix reporting select with cycle-aware choices. Preserve these owners.
- `AgentAvatar.tsx` and `avatar-lab/renderer.ts`: a shared SVG scheduler, viewport visibility tracking, hidden-document suspension, reduced-motion handling, and sparse scheduling. Keep the muted avatar palette independent from neutral selection. No React Bits avatar or particle engine is warranted.

Experience First shaped the recommendation: improve feedback in the existing workflow and leave unnecessary effects out. Type System Discipline shaped the state recommendation: use actual operation states and receipts, never a demo timer that manufactures completion.

## Dependency and performance interpretation

Pinned registry entries specify `motion@^12.23.12` for ThoughtLine, PromptBar, StatusMark and WarmTooltip. Pebble uses Motion **14.3.0**, React **19.3.0**, and Lucide **1.58.0**. Blind CLI installation could rewrite dependency choices; compatible-looking APIs are not verification against Motion 14. Keep the pinned app stack and existing icons.

ThoughtLine, PromptBar, CallChip, GlideSelect, AnimatedList and Stepper add `@hugeicons/react@^1.1.10` and `@hugeicons/core-free-icons@^4.3.3`. WarmTooltip also declares `react-dom@^19.0.0`. AnimatedContent declares `gsap@^3.13.0`. ShinyText has no registry dependencies. These facts are verified in the pinned `public/r/<Component>-TS-CSS.json` files, for example [ThoughtLine registry](https://github.com/DavidHDev/react-bits/blob/310fc737fadcaa149a4e06fb088fc95332dc8bfb/public/r/ThoughtLine-TS-CSS.json).

RAF loops, observers and layout reads above identify workload and compatibility concerns; they are not measured frame-rate, memory, battery or bundle-size results. A small footprint must be verified in a built artifact. Webview parity also requires checking real Safari/WKWebView and Windows WebView2; browser emulation alone cannot establish native-platform consistency. Prefer the existing CSS/Motion/Radix stack to avoid multiplying behavior across future shells.

It is not plain MIT. Its short wording is different from the standard [Commons Clause text](https://commonsclause.com/), so assess the actual file rather than importing a generic interpretation of that name.

A paid Pebble app is not categorically prohibited by this text. Copying a component into a whole app appears to fit its express application permission. Selling an extracted UI kit or port does not. A public Pebble repository should preserve this third-party license and notices rather than claiming copied files are unrestricted MIT; the redistribution boundary matters for reusable exports and downstream relicensing. If an unrestricted open-source distribution promise is a product requirement, implement independently from the interaction idea or resolve permission before copying source. This report recommends the former for the top changes, which also avoids new engines and dependency versions.

## Minimal integration sequence and acceptance evidence

1. First tune the existing TooltipProvider. [Radix officially exposes](https://www.radix-ui.com/primitives/docs/components/tooltip) `delayDuration` and `skipDelayDuration`; the current wrapper overrides the initial delay to zero. Test cold hover, adjacent controls, keyboard focus, Escape, disabled controls and screen-edge placement. A phone tap must continue to activate the control directly. Keep labels available to assistive technology without requiring hover or long press.
2. Next try only activity exit/label settlement in the actual production app. Use the existing reserved lane and stable live-turn identity. Keep all copy derived from real runtime activity; never start a simulated completion timer. Verify sending, first reply, activity changes, stop, failure, reaction during streaming, stream receipt reconciliation and a reader scrolled up. The settled view should not gain a permanent completion ornament. Reduced motion should be static and no row/timestamp should remount or shift because of settlement.
3. Then evaluate the small send/stop glyph treatment against the existing control, only keeping it if it improves recognition. Preserve keyboard focus, action semantics, no accidental extra submit/stop, exact composer/control center alignment, mobile hit areas, draft restoration and upload gating. Test IME composition, Enter/Shift+Enter, phone keyboard opening, long multiline drafts, reconnect and cancellation. Do not expose models, effort, sources or dictation until actual product capability supports them.
4. Consider Status Mark later, only after identifying a specific operation whose present feedback is inadequate. Do not replace the existing file-list LoadingBar or add another avatar status engine.

For any implementation, run `npm run check`, relevant production desktop and phone flows from `.agents/skills/verify`, and inspect settled desktop/iPhone/Android screenshots. Run the isolated native-owner check if a chat/profile/setup/avatar contract changes. Measure any claimed performance benefit against the current app on the same device and workload; verify zero new perpetual decorative loops and no new animation engine in the produced bundle. The future Crew section, group-chat creation, initial DM placement, and ad hoc chat semantics are outside this visual research and must not be altered to fit a component.
