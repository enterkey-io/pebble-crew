# Hermes-owned voice and video calls

Every conversational reply in a call must come from the selected Pebble's existing Hermes Bot Chat. The same profile, SOUL, memory, model, tools, and approval rules apply in text, voice, and video. Speech services transcribe the caller or read Hermes's words aloud. Atmee animates the avatar from that audio. This plan supersedes the provider-led conversation design in the earlier voice and Atmee plans.

## Why the current calls sound different

The private preview uses three provider-led conversations. OpenAI GPT-Live decides when to delegate and can paraphrase the result. ElevenLabs generates replies and can call `ask_pebble`. Atmee runs its own conversation and can call the same tool. Adding profile hints to those sessions leaves reply authorship with the provider.

The OpenAI chat issue has a direct path in the preview source. `VoiceChat.onDelegation` gives provider-supplied request text priority over the microphone transcript. `voice.submit` then passes that text to native `prompt.submit` as a regular user turn. Fix the input boundary along with the speaker. [Reviewed preview source](https://github.com/enterkey-io/pebble-crew/commit/6bfeadd84b5a4d04a950f0a81ca884511987bb6e)

The cause of the reported lip-sync failure remains unverified. The current browser can choose incoming audio and video from different publishers. The replacement must play Atmee's paired audio and video from the same renderer, then measure the result.

## 1. Route the entire call through Bot Chat

- Bind each call to an authorized owner, profile, and canonical conversation. Accept one committed microphone transcript per call and utterance ID. Save it with spoken-user provenance. Keep partial captions, application notices, and tool inputs out of user messages.
- Use the existing native submit and queue path. On the Hermes host, persist the mapping from utterance to native receipt and final assistant message. Verify queued-turn correlation and durable deduplication on the supported Hermes builds. If the native outcome is uncertain, reconcile it before resubmitting. Never identify a reply by choosing the latest assistant message.
- Send only the matched, user-visible Hermes reply to synthesis. Keep approvals in the existing chat cards. An ambiguous spoken confirmation never resolves a card. Hangup or barge-in stops playback immediately. Hermes handles cancellation separately through its existing controls, so a media interruption cannot imply that tool work was undone.
- Keep one call record and the real voice turns in the same Bot Chat. Record delivery status separately so reconnects or an interrupted answer cannot create duplicate messages or replay stale speech. If a call needs a follow-up, Hermes writes it from the canonical call turns. Internal follow-up instructions stay out of user bubbles.
- Retire provider-led call entry points as part of the cutover. Preserve saved credentials, voices, avatars, and historical records. Keep a supported audio option available if video fails. A provider error shows as call status and cannot start a substitute conversation.

## 2. Deliver voice first

Start with one full call through ElevenLabs Scribe for transcription and ElevenLabs streaming text-to-speech for the selected voice. This uses the same basic flow as Vox. Play synthesized audio as it arrives, without waiting for a whole audio file. Start with the completed Hermes reply. Add speech from earlier phrases only if native Hermes can identify text that is committed, user-visible, and part of that exact turn. [ElevenLabs streaming transcription](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/server-side-streaming) · [ElevenLabs streaming speech](https://elevenlabs.io/docs/eleven-api/guides/how-to/websockets/realtime-tts)

OpenAI can transcribe in a transcription-only session. Its dedicated speech models are scheduled to retire on January 6, 2027. The documented replacement reads aloud via a prompted Realtime model. Evaluate it as a separate, isolated speech adapter with only Hermes-authored text and no microphone, tools, or history. Qualify it only if the app can verify the spoken words before playback and suppress additions or rewrites. If that gate fails, keep ElevenLabs as the supported voice output. [OpenAI live transcription](https://developers.openai.com/api/docs/guides/realtime-transcription) · [OpenAI speech model retirement](https://developers.openai.com/api/docs/deprecations#2026-10-01-text-to-speech-models) · [OpenAI read-aloud workflow](https://developers.openai.com/api/docs/guides/custom-voices)

## 3. Test Aurora in Atmee Avatar-only mode

- Reuse Aurora's existing portrait and avatar ID. Open an Atmee render session, send the selected voice's audio as 16 kHz PCM through LiveKit, and play the renderer's paired audio and video. Use one playback path with no second copy of the synthesized audio. Atmee's built-in conversation voice and behavior are separate from Avatar-only. Start with Aurora's selected Pebble voice, since Atmee does not document exporting her recorded Atmee voice for external synthesis. [Atmee render session API](https://www.atmee.ai/docs/api/reference/avatar-sessions/startAvatarSession) · [Atmee LiveKit integration](https://www.atmee.ai/docs/livekit-plugin/livekit-agents-plugin)
- Use an owner-controlled LiveKit room with distinct, short-lived grants for the browser, owner-side worker, and renderer. Atmee's hosted-room response documents a privileged agent token. Consider hosted rooms only if Atmee documents a separate, appropriately scoped browser grant. Keep provider keys and room-signing secrets on the owner side. [Atmee room and token contract](https://www.atmee.ai/docs/api/reference/avatar-sessions/startAvatarSession)
- Keep the mirrored self-view in the lower right and the camera off initially. When the owner shares their camera, route visual input to Hermes. First prove that the selected Hermes model can answer questions about current frames during a call through its existing image-input path. Scope camera access to the owner-side worker. The renderer needs Aurora's audio.
- Set the first live render session to the documented 60-second minimum ceiling. Standard V2 Avatar-only lists at 1 Atmee credit per minute, with speech and any LiveKit costs separate. Show renderer warm-up clearly, stop the session on hangup or teardown, and confirm billing stopped from the receipt. V2 can take minutes to start cold. [Atmee pricing](https://www.atmee.ai/pricing) · [Atmee session limits and warm-up](https://www.atmee.ai/docs/api/reference/avatar-sessions/startAvatarSession)

## What has to pass before release

1. Run native-owner acceptance with a disposable Hermes profile and synthetic audio. Prove one owner row per committed utterance, exact native reply matching, memory recall, a real tool call, and an approval that stays pending until the owner acts. Inject a provider-authored request and verify it never reaches chat or Hermes as the owner. Exercise duplicate delivery, lost acknowledgments, reconnect, and interruption during a tool call.
2. Compare short voice turns in desktop and real phone browsers. Measure end of caller speech to first audible reply, and measure time to silence when interrupted. Separate Hermes response time from transcription, synthesis, and playback. Use these measurements to decide if earlier phrase streaming is worth adding.
3. For video, play a repeatable speech clip and check warm starts, reconnects, and drift. Measure mouth-to-audio skew and review how often the mouth moves during voiced sections. Test the real Aurora avatar within the short session ceiling. Keep video in preview until it passes a visual review on desktop and a phone. Verify camera understanding by showing Hermes an object without naming it.
