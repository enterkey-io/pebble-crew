# 0.7.9-preview.1

Live-update recovery keeps a healthy Hermes chat usable instead of repeatedly
replacing its connection and cancelling requests. One browser session now owns
ticket renewal, lease replacement, stream retries, native-health checks and
resource recovery. Drafts, navigation and feature editors keep their identity.

The plugin isolates tab leases, filters unrelated events before queue admission,
and replaces stream subscriptions without old cleanup closing their successors.
Recovery reads an existing conversation without resuming or provisioning it.
After a native restart, only the affected conversation rebinds. Delayed old
bearers cannot shorten renewed authority. Dispatched writes are never replayed.

This release also includes the pending Tasks loading correction. Temporary board
read failures retry once; persistent failures use the shared recovery UI, keep
loaded tasks mounted and retain safe error codes. Board authentication recovery
refreshes through the stable session without discarding the current board.

The protocol stays `hermes-bot-web.v1`. The optional `connection_recovery: 1`
capability adds read-only snapshots and model-free native status. NDJSON framing
and heartbeat cadence remain unchanged. Existing independent hosting is retained.
See [connection recovery](../CONNECTION_RECOVERY.md) and
[the wire protocol](../WIRE_PROTOCOL.md).

## Update

Use the [tagged installer guide](https://github.com/enterkey-io/pebble-crew/blob/v0.7.9-preview.1/docs/AGENT_INSTALL.md).
Verify both manifest and checksums. Preserve owner state, signing keys, credentials,
profile data, ingress and supervisor settings. Update the complete combined
plugin rather than browser files alone. Do not reset browser access or run model
checks on an owner's installation.

The build and native acceptance evidence records exercised synthetic paths.
It does not identify the original owner's network trigger or claim every ingress
has been tested. Publishing this release does not update an owner's installation.
