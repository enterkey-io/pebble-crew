# Pebble Crew 0.7.8-preview.24

Private agent conversation links and their open viewer now update when replies
arrive. Counts remain in chat history after later messages and page reloads.
A peer reply automatically wakes the initiating agent once in the private thread.
The agent also receives recent private conversation context in its own Bot Chat.
Private content is excluded when another agent requests that agent's role card.

- Crew collapse arrows stay within their rows. Crew members remain indented,
  with smaller grouped avatars and separate touch targets on phones.
- The New menu uses the requested order: pebble, crew, group chat, section,
  task, project board. Every item uses the New label.
- Reply capacity is reserved before an agent sends a private request, so an
  admitted request can notify its initiator when the peer finishes.

The bridge emits content-free `exchanges.changed` events. The browser refreshes
conversation references after reconnecting and retains polling for older bridges.
No new service, external storage or owner setup is required.

Validation includes the production desktop and phone flows, native private
request/reply delivery, history after reload, and the installed-package update
and rollback checks in disposable Hermes homes. Tests use a deterministic local
model. Installation and update checks do not run owner models.

Use the [tagged upgrade guide](https://github.com/enterkey-io/pebble-crew/blob/v0.7.8-preview.24/docs/AGENT_INSTALL.md).
Activate the host first, synchronize runtimes while native work is stopped, then
restart the existing supervisor and stopped profile processes. Preserve the
existing login, private state, credentials, ports and HTTPS route. No pairing or
onboarding reset is needed. Publishing this release does not upgrade an owner's
installation.
