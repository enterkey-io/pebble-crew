# v0.7.11-preview.1

Pending approvals, questions and secret requests occupy the conversation's input
area until handled. The compact queue keeps one request visible, shows **1 of N**,
and offers previous/next and **Read more**. Message drafts, attachments and unfinished
answers stay intact through scrolling, conversation switches and reconnects.
Resolved requests leave small chronological receipts in the chat.

Pending management requests are discovered independently of completed history,
in bounded consistent pages. Exact-ID recovery and decisions no longer search a
truncated history list. An unreadable row stays visible as a problem without
hiding healthy requests. Unknown outcomes are never automatically replayed.

Existing pending creation proposals can survive unrelated workspace edits.
Approval checks the actual agent, manager and model bindings. Older requests
without a recorded manager identity require an explicit review of the current
binding, under their original request ID and fingerprint. Replaced identities,
changed model authorization and uncertain earlier creation still block execution.

**Files** is now **Library**. It includes authorized photos, videos and documents
shared by agents in native Bot Chat history, alongside owner uploads. Existing
image/video and document viewers work from Library; private paths, hidden messages
and remote images are not cataloged or fetched.

Verification uses the actual production app on desktop, iPhone and Android,
plus disposable native Hermes homes and deterministic loopback models. It does
not establish the cause of a particular owner's missing request or ingress issue.
Native tool/question/secret receipts remain in the signed-in app session;
management receipts remain in the owner-local journal across reloads.

Local checks passed: 265 unit tests, 403 plugin tests, 29 desktop journeys,
57 iPhone/Android journeys, and 9 native owner journeys. The existing WebKit
WebRTC loopback probe is skipped because it produces no ICE candidates in the
automation environment; these checks do not prove physical Safari voice behavior.
Settled light/dark desktop and phone screenshots were inspected. Native card and
media checks passed on both pinned Hermes builds. Exact-package installation,
host-first update, crash recovery, explicit rollback and failed activation passed;
install/update paths ran no model turns. The full owner-browser suite targets the current pinned build: authenticated
private-agent threads are unsupported on the legacy build. Its dedicated native
exchange test confirms safe refusal, and the new approval and Library scenarios
passed on both builds.

Use the tagged [upgrade guide](https://github.com/enterkey-io/pebble-crew/blob/v0.7.11-preview.1/docs/AGENT_INSTALL.md).
Preserve state and existing pending IDs. Do not duplicate requests, reset browser
access, approve outside the owner interface or run test prompts on an owner's install.
